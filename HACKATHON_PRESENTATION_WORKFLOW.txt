1. EXECUTIVE SUMMARY & PROBLEM-SOLUTION FIT
================================================================================

THE PROBLEM (Why 2D Cadastre Fails Modern India):
India's Bhu-Aadhaar (2D-ULPIN) assigns a 14-character alphanumeric identifier to
land parcels based on their 2D geographic bounding polygon. While revolutionary for
rural land and horizontal surface boundaries, 2D cadastral systems collapse in
high-density vertical urban environments:
1. Multi-Storey Overlaps: 100 residential flats stacked on the exact same ground
   footprint share the identical 2D coordinate boundary, making unit-level legal
   rights, mortgages, and tax assessments indivisible in spatial GIS.
2. Subterranean & Air Rights Blindspots: Metro rail tunnels, underground utility
   conduits, multi-level basement parking, flyovers, and elevated transit corridors
   pass above or below private land parcels without volumetric spatial demarcation.
3. Volumetric Encroachments: Unauthorized floor extensions, cantilevers over public
   right-of-ways, and basement encroachments beyond legal property lines cannot be
   detected by 2D GIS overlay analysis.

THE SOLUTION (Bhumi3D):
Bhumi3D pioneers India's first Unified 30-Character 3D-ULPIN (Bhu-Aadhaar 3D) system.
It extends the national 2D standard into volumetric, watertight 3D Polyhedral
Surfaces (X, Y, Z AMSL) featuring:
- Sub-Centimetre 3D Parcel Geometry stored natively in PostGIS (POLYHEDRALSURFACE Z).
- Automated 3D Clash Detection Engine calculating exact volumetric overlaps (> 0.05 m3).
- Computer Vision & ML Floor Plan Ingestion parsing architectural blueprints directly
  into georeferenced 3D cadastral units.
- Dual-Perspective WebGL Engine (CesiumJS) with subterranean cut-away rendering.
- 3-Phase Zero-Knowledge RBAC ensuring strict DPDP privacy compliance for land records.

4. CORE MATHEMATICAL & ALGORITHMIC ENGINES
================================================================================

--------------------------------------------------------------------------------
ALGORITHM 1: STANDARDIZED 30-CHARACTER 3D-ULPIN GENERATOR (Bhu-Aadhaar 3D)
--------------------------------------------------------------------------------
Format Specification:
[Base-2D-ULPIN]-[Spatial-Layer][Base-AMSL][Floor-Code]-[Unit-ID]-[CRC8]
Example: KA010010420104-S0923F01U001-D7

Component Breakdown:
1. Base 2D ULPIN (14 chars): State ('KA') + District/Taluk ('01001') + Ward ('042') + Parcel ('0104')
2. Spatial Layer Code (1 char):
   - 'S' = Surface / Above-Ground Building Unit
   - 'U' = Underground / Subterranean (Basements, Metro, Utilities)
   - 'A' = Airspace Rights / Cantilever / Drone Corridor
3. Base Elevation AMSL (4 chars): Ground elevation in metres above MSL ('0923' = 923.0m)
4. Floor Level Code (3 chars): 'F01'..'F99' (Floors), 'GF0' (Ground), 'B01'..'B10' (Basements)
5. Unit Identifier (4 chars): 'U001'..'U999' (Flats), 'METR' (Metro), 'UTIL' (Utility), 'COMM' (Common)
6. CRC-8 Integrity Checksum (2 chars):
   - Generator Polynomial: P(x) = x^8 + x^2 + x + 1 (0x07, Initial Value: 0x00)
   - Protects against keying errors, database corruption, or malicious forgery.

Python Reference Implementation:
def compute_crc8(payload: str) -> str:
    crc = 0x00
    for byte in payload.encode('ascii'):
        crc ^= byte
        for _ in range(8):
            if crc & 0x80:
                crc = ((crc << 1) ^ 0x07) & 0xFF
            else:
                crc = (crc << 1) & 0xFF
    return f"{crc:02X}"

--------------------------------------------------------------------------------
ALGORITHM 2: ANDREW'S MONOTONE CHAIN 2D CONVEX HULL (O(n log n))
--------------------------------------------------------------------------------
Problem:
In multi-tenant apartment complexes, individual floor slabs are partitioned into 4
quadrant flats (NE, NW, SW, SE). Rendering any single flat polygon in Monolithic
Envelope Mode leaves 3/4 of the building missing.

Solution:
Bhumi3D aggregates all vertex points across all units of a building and runs Andrew's
Monotone Chain algorithm to construct the unified outer building perimeter.

Mathematical Steps:
1. Collect all vertex coordinate pairs (xi, yi) from all unit polygons of the building.
2. Sort points lexicographically by x (longitude), then by y (latitude).
3. Compute 2D Cross Product of vectors OA and OB:
   Cross(O, A, B) = (Ax - Ox) * (By - Oy) - (Ay - Oy) * (Bx - Ox)
4. Construct Lower Hull: Iteratively append points; while the last 3 points make a
   non-left turn (Cross <= 0), pop the middle point.
5. Construct Upper Hull: Repeat in reverse order.
6. Concatenate Lower and Upper hulls (omitting duplicates) to produce the exact
   watertight 2D base envelope for building extrusion.

--------------------------------------------------------------------------------
ALGORITHM 3: 3D VOLUMETRIC CLASH & ENCROACHMENT DETECTION ENGINE
--------------------------------------------------------------------------------
Mathematical Formulation:
Overlap Volume (V_overlap) = Area(Footprint_A ∩ Footprint_B) * max(0, min(z_max^A, z_max^B) - max(z_min^A, z_min^B))

Detection Pipeline:
1. Broadphase Filter:
   PostGIS 3D bounding box index (&&& operator) filters non-proximate entities in <5ms.
2. Narrowphase 2D Footprint Intersection:
   Shapely 2D polygon intersection computes shared surface area (A_intersect).
   Contact boundaries with A_intersect = 0 (shared structural walls) are excluded.
3. Vertical Z-Overlap Calculation:
   Delta_Z = min(z_max^A, z_max^B) - max(z_min^A, z_min^B)
4. Volumetric Threshold Filter:
   If Delta_Z > 0 and V_overlap > 0.05 m3, flag as structural clash.
   Compute exact intersection solid geometry and store in spatial_clashes table.

6. 3-PHASE ZERO-KNOWLEDGE ROLE-BASED ACCESS CONTROL (RBAC)
================================================================================

Bhumi3D enforces strict privacy compliance with India's Digital Personal Data
Protection (DPDP) Act using a 3-Phase progressive disclosure architecture:

Phase 1: Guest / Citizen (Unauthenticated Public Cadastre)
- Spatial Access: Public 3D building envelopes, 2D Bhu-Aadhaar ULPIN, 3D-ULPIN,
  cadastral plot numbers, ward/district names, building height, total volume.
- Privacy Masking: All personally identifiable information (PII) is masked:
  e.g., 'Vikram Malhotra' -> 'V****m M******a', contact numbers & deed IDs hidden.
- Privileges: View-only 3D skyline exploration, sub-surface viewing.

Phase 2: Verified Citizen (OTP / DigiLocker Authenticated)
- Spatial Access: Unlocks interior floor slabs and flat boundaries for properties
  verified under the citizen's Aadhaar/DigiLocker account.
- Privacy Masking: Citizen sees their own full title record unmasked; neighboring
  units remain masked.
- Privileges: File 3D volumetric dispute grievances, download verified 3D Title Deeds.

Phase 3: Cadastral Officer / Admin (Government Land Revenue Authority)
- Spatial Access: Full unrestricted access to all surface parcels, underground utility
  easements, and transit corridors.
- Privacy Masking: Full unmasked deed registry across all units.
- Privileges: Edit unit attributes, regularize spatial overlaps, adjudicate grievances,
  and execute administrative PostGIS transactions.
